# Work-note template

Copy the sections below into the actual private `.md` step document. Replace every bracketed field with actual evidence or an explicit gap; this template is not completed work. A related small action can share a note if every accepted action ID has a stable section destination.

## Identity and outcome

- Step/action IDs: [actual IDs].
- Status: [draft/provisional/completed/blocked/not-applicable].
- Owner and review time: [person/role and dated evidence].
- Authorized scope and boundary: [site, routes, languages and allowed actions].
- Outcome: [what is verified at this stage].

## Inputs and evidence

List actual source captures, inventory revision, query IDs, dates, methods, URLs and immutable artifact hashes. Explain unavailable inputs instead of treating absence as zero. Private fields remain private.

## Findings and decisions

Record observed facts separately from interpretations. For each action, include evidence, the decision, affected exact canonical/Markdown destinations, dependencies and no-action rationale where appropriate.

## Implementation and verification

Record exact source changes, candidate/commit hashes and scope-matched checks. Local acceptance, actual release delivery and provider/engine outcomes are separate states. For native hint edits, compare robots records and XML elements before/after and check delivered raw comment retention.

## Maintenance, limitations and rollback

Record known gaps, refresh triggers, content/route deletions, cache behavior, maintenance owner and a concrete revert path. Do not mark the whole job complete while a required check is missing.

## Direct next destination

Link to the next actual note and answer-bearing resource or evidence record. Register the current note and hash in the private work `index.md`; final work validation must find no stale, broken or unresolved steps.
