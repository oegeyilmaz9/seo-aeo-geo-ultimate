# Search-result presentation contract

Use this contract when a page is meant to gain or defend organic visibility, improve search-result click-through, or ship as part of a broad SEO implementation. A narrow task outside this surface does not automatically expand into a full-page rewrite.

## Required page-level evidence

Record the requested and canonical URL, intended indexability, locale/device, page role, primary need/query family, raw and rendered title/H1/meta description, current search-result observation when available, and the capture date. Check title/H1 alignment without requiring identical wording.

Treat each of these as an explicit state: present and page-specific; present but generic/duplicated; missing; conflicting across raw/rendered output; or unverified. Do not let “present” stand in for “useful.”

## Description completeness

A page-specific meta description should give a searcher enough truthful information to decide whether the result fits. Check for:

- page identity or subject;
- the useful outcome, answer, product, service, or task available on the page;
- a concrete differentiator, scope detail, or source-backed fact that distinguishes this URL;
- a material qualifier such as location, audience, availability, date, price scope, or limitation when it affects the decision.

Not every description needs every optional qualifier. A fragment such as only a product/category name is under-informative even though it is technically non-empty. Duplicate boilerplate, keyword lists, unsupported superlatives, and padded filler also fail. Google publishes no fixed meta-description length; use semantic completeness and rendered/device review rather than a hard character count.

For an implementation-ready handoff, provide the actual proposed title and description plus the facts they rely on. “Improve metadata” is not a completed copy deliverable.

## Hostname identity handoff

Page review records whether the hostname has a home-page favicon declaration and whether the observed search result shows the intended brand identity. `seo-technical` owns file delivery, crawl access, format/dimensions, and live verification. `seo-content` owns approved title/description wording. `seo-schema` owns truthful `WebSite` site-name markup when that is part of the approved scope.

## Acceptance

Verify the exact raw and rendered candidate, uniqueness across the affected page set, canonical/indexability agreement, and live search-result delivery inputs. Search engines may generate a different title link or snippet for a query, so acceptance proves eligible, complete inputs—not the final presentation or ranking.
