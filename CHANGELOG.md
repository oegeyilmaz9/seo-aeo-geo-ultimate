# Changelog

All notable changes to SEO-AEO-GEO Ultimate are documented here.

## [3.1.0] - 2026-08-20

### Added

- A decision-and-release contract that keeps product intent, implementation, deployment, provider mutation, and delayed provider outcomes as independent phases.
- Provider operations mode for Search Console, Bing Webmaster Tools, and IndexNow with a hash-bound `provider-operation-receipt.json` schema and semantic validator.
- A generic read-only live-release verifier for sitemap equality, indexable documents, redirects, shared surfaces, transient recovery, and machine-readable closeout counts.
- Programmatic SEO contracts that separate editorial readiness from indexability and propagate canonical/search decisions across the full affected corpus and discovery surfaces.
- Scope-matched live verification, external audit-claim adjudication, dirty/generated candidate identity, external closeout, and per-action/batch-final/production-comparison verification protocols.
- A broad organic-growth completeness gate for query-to-page ownership, title/meta copy, canonical/indexability, and hostname favicon identity; plus evidence-layered query-opportunity and snippet-copy protocols.
- A mandatory two-track keyword ambition contract: nearer-term gains run alongside high-volume head-term/category leadership, with difficult strategic targets retained through staged content, authority, architecture, and visibility milestones.
- A manifest-derived orchestration ledger initializer and validator that turns the router's complete 27-skill screen into executable closeout evidence.

### Changed

- Promoted `seo` from a specialist dispatcher to the autonomous suite core: every request receives a 27-skill applicability screen, required specialist instructions and artifacts are carried internally, and the user receives one consolidated result without coordinating SEO/AEO/GEO terminology or handoffs.
- Kept specialist loading progressive: the router screens every capability, then loads only applicable full workflows while the ledger validator prevents silent omissions at broad closeout.
- Extended the router through product-owner decision, local acceptance, separately authorized release, live delivery verification, separately authorized provider operations, and delayed outcome follow-up.
- Preserved explicit product-owner end states ahead of the implementation preference for the smallest reversible change.
- Refreshed primary-source capability boundaries for Google AI search, Search Console, the Google Indexing API, Bing submission, OpenAI search crawling, and Anthropic search/user/training crawlers.

### Guardrails

- A local pass is not a production release; a deployment is not a provider operation; an accepted sitemap or URL notification is not a crawl, indexing, ranking, retrieval, citation, referral, traffic, or conversion result.
- Shared template, resolver, sitemap, canonical, redirect, hreflang, and corpus changes must be verified over their affected universe rather than closed from a small illustrative sample.
- Keyword opportunity selection must preserve first-party query/page context, dated result-set intent, business/page fit, authority and risk; it cannot be reduced to volume, density, or a universal keyword score. Relevant high-volume owner targets cannot be deferred solely because they are difficult, expensive, currently absent, or authority-constrained.

## [3.0.0] - 2026-08-10

### Added

- Formal Query Corpus and conventional SEO Performance Run contracts with provenance, coverage, data-quality, arithmetic, and comparison validation.
- Visibility Run `2.0.0` retrieval traces, repeated observations, disclosed executed queries, consulted-source versus citation separation, citation-to-claim reviews, and confidence metadata while retaining legacy `1.0.0` support.
- Commerce, local, video, news/Discover, agentic web, site architecture, and authority/source-landscape specialist skills.
- Hash-pinned Site Graph validation and a dated Platform Controls registry for feature lifecycle, crawler purpose, change notifications, and protocol capabilities.
- A maintained `llms.txt` publisher-guide workflow with a reusable template, root example, portable validator, platform-control entry, and regression tests.
- Deterministic draft scaffolding, validator-gated artifact migrations, readable validated reports, and two sanitized end-to-end example bundles.
- Credential-free import adapters for Google Search Console, Bing Webmaster Tools, organic GA4, crawler CSV, and Apache/Nginx logs with raw hash provenance and privacy boundaries.
- Migration/replatforming, search-traffic incident, manual-action, hacked-site recovery, and controlled SEO experiment operating protocols.
- Expanded source registry coverage for Search Console queries, ecommerce, local, video, news, agentic UX, IndexNow, OpenAI/Anthropic web search, commerce protocols, and cross-engine research.

### Changed

- Expanded Research Pack to `1.1.0`, SEO Findings to `1.1.0`, Optimization Brief to `1.1.0`, and Action Plan to `1.2.0` for hash-bound evidence and the new specialist owners and targets while keeping legacy artefacts readable.
- Expanded the default `seo` router from 19 to 27 focused skills and kept conventional search performance separate from AI visibility measurement.
- Bumped the shared Codex and Claude Code package to `3.0.0`.

### Hardened

- Bound Research Pack `1.1.0` provenance and SEO Findings `1.1.0` evidence to exact raw SHA-256 captures; direct observations also bind target ID, locale, and URL or a target-specific envelope.
- Kept every Action Plan finding inside its declared target/locale scope and inherited high-risk treatment from policy, accessibility, and documented crawler-control work.
- Required explicit Action Plan `1.2.0` risk flags for policy, crawler/indexing, legal/privacy, accessibility, experiment-wide, and irreversible work; legacy Action Plans remain readable but their current risk review is deliberately manual rather than inferred by migration.
- Bound SEO Performance drift to explicit prior/current records, validator-derived values, source context, data-quality context, and optional observed-search Query Corpus membership.
- Bound Visibility Run `2.0.0` to frozen device/location/conversation context, declared executed-subquery lineage, collection-context comparability, and recomputed Wilson intervals.
- Bound Site Graph nodes to hash-pinned metadata envelopes and edges to parsed anchor elements/source captures, prevented reused captures, and rejected backdated Platform Controls validation.
- Made validator paths portable across Claude Code plugin installs and Codex repository checkouts.
- Made Codex installs self-contained with immutable support packages, runtime locators, tamper verification, and safe backups.
- Added optional bounded live-link checks for `llms.txt`, scheduled freshness validation, and one deduplicated GitHub review issue that closes after recovery.
- Kept `llms.txt` useful but honest: optional future-readiness when it can stay correct, with public-URL safety checks and no ranking or retrieval claim.
